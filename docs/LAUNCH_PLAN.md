# Mind Record — 출시 계획서 (검증용 초안)

> 목적: 이 문서는 현재 앱 상태, 남은 작업, 그리고 가격/결제/비용 구조에 대한 제안과 옵션을 정리한 것입니다. 각 항목의 "선택지"와 "제안"을 구분해 두었으니, 제안이 최선인지 다른 관점에서 검토해 주세요. 특히 **§6 원가 모델, §7 가격, §8 결제 구조**에 대한 의견을 원합니다.

## 1. 제품 요약

**Mind Record**는 음성 저널링 앱입니다. 사용자가 말하면 앱이 받아써서 요약하고, 할 일(task)과 아이디어(idea)를 자동으로 뽑아 토픽별로 정리합니다.

두 가지 입력 모드:
- **Capture(녹음형)**: 끊기지 않는 녹음. 일시정지/재개 가능. Done을 누르면 전체를 한 번에 처리.
- **Conversation(대화형)**: AI와 음성으로 주고받음. 말을 멈추면 AI가 답하고, 자동으로 다시 듣기 시작(핸즈프리). "저장하고 끝내"라고 말하거나 버튼으로 종료.

처리 파이프라인: `오디오 → Whisper(STT) → 텍스트 → GPT-4o-mini(요약/outline/task/idea 추출 + 토픽 배정) → DB`. 대화형은 턴마다 `Whisper → GPT → TTS`.

화면: Home / Records(날짜별) / Topics(계층 토픽, 미분류) / Tasks / Search, 그리고 Account(설정).

## 3. 현재 상태 (2026-09-19 기준)

### 동작하는 것
- 두 모드 모두 녹음 → 처리 → Summary 화면(요약 카드, outline, task/idea, transcript)
- 대화형 핸즈프리 루프(침묵 감지는 노이즈 플로어 상대 기준, 실기기 튜닝 진행 중)
- 토픽 계층(1단계), 미분류, 이름변경/이동/병합/삭제, 음성으로 "X 토픽 만들어줘"
- Tasks CRUD, 마감일, 완료 처리
- Records 달력/목록, 커서 페이지네이션
- AI 개인화: AI 이름, 호칭, 목소리(4종+미리듣기), 답변 언어(Auto/한국어/English)
- **음성 인식은 언어 자동 감지** (Whisper에 언어 힌트 안 줌). UI는 영어.
- 처리 성공 후 오디오 자동 삭제(텍스트만 보관) — 저장 비용 억제

### 최근 전체 코드 감사에서 수정한 것 (참고)
대화 루프의 재생 종료 감지 버그, 종료/취소 시 진행 중 턴과의 경쟁 상태, 녹음 일시정지-종료 경쟁, 25MB Whisper 제한(모노 64kbps로 변경), Summary 폴링 무한 대기, 서버 insert 에러 무시, 파일 경로 소유권 검증, 키보드가 입력창 가림, 안드로이드 edge-to-edge 모달 잘림, 인증 콜드스타트 깜빡임, 이미 가입된 이메일 안내 오류 등.

### 알려진 미해결 / 약점
- **Search**: 최근 100개 항목 클라이언트 문자열 필터. "내 기록 전체에 자연어로 질문"은 미구현.
- **백그라운드 녹음**: 화면을 끄면 Android가 마이크를 끊음. 켜려면 알림 권한 흐름 필요.
- 침묵 감지 파라미터는 실기기 데이터로 튜닝 필요.
- 오디오 인터럽트(전화 수신, 블루투스 전환) 처리 없음.
- 온보딩, 개인정보처리방침/약관 화면, 계정 삭제 없음 (스토어 필수).

## 5. 설계 옵션 (의견 요청)

### 5.1 Search
- (a) 서버 `ilike`/Postgres full-text로 transcript·요약·task·idea 전체 검색. 단순, 저렴. **← 제안(출시 전)**
- (b) pgvector 임베딩 + 유사도 검색. 의미 검색 가능. 임베딩 비용·인프라 추가.
- (c) 전체 기록을 GPT에 넣고 자연어 질문 답변. 사용자가 원하는 경험이지만 기록이 많아지면 컨텍스트 한계·비용. (b)+RAG로 가야 함. **← 출시 후**

### 5.2 STT 모델
- (a) `whisper-1` $0.006/분. 검증된 다국어. **← 현재**
- (b) `gpt-4o-mini-transcribe` $0.003/분. 절반 가격. 한국어 등 정확도 실측 필요.
- (c) 온디바이스 STT(Android SpeechRecognizer/iOS Speech). 무료지만 정확도·언어 일관성 떨어지고 백그라운드 제약. 비추천.
- **질문**: (b)로 전환해 원가를 절반으로 낮출 가치가 있는지? 어떤 검증 방법이 좋은지?

### 5.3 백그라운드 녹음
- (a) foreground service + 알림 권한 요청(Android 13+). 표준 방식. **← 제안**
- (b) 앱이 백그라운드로 가면 자동 일시정지하고 알려줌. 구현 쉽지만 UX 나쁨.

### 5.4 대화형 답변 언어
- 현재: Auto(말한 언어) / 한국어 고정 / English 고정. UI는 영어 고정.
- **질문**: 스토어 출시 시 UI 다국어(i18n)가 필수 수준인지, 영어 UI로 시작해도 되는지?

### 6.2 풀링(pooling) 전제
OpenAI 청구는 회사 단위이므로, 가격은 **개인별 잔량이 아니라 사용자 평균 사용량** 기준으로 책정. 적게 쓰는 다수가 많이 쓰는 소수를 상쇄(헬스장 모델).

가정한 사용 분포 (구독 앱 일반 패턴, **실측 전 추정치**):

| 유형 | 비율 | 하루 사용 | 월 원가 |
|---|---|---|---|
| 거의 안 씀 | 40% | 2분 | $0.4 |
| 가끔 | 35% | 8분 | $1.7 |
| 꾸준히 | 20% | 20분 | $4.3 |
| 헤비 | 5% | 60분 | $13 |
| **가중 평균** | | **~11분/일** | **~$2.5/월** |

**질문**: 이 분포 가정이 합리적인지? 음성 저널링은 일반 앱보다 "꾸준히" 비율이 높을 수 있음. 보수적으로 평균 20분(월 $4.3)으로 잡아도 가격이 성립하는지 검토 바람.

### 6.3 꼬리 위험과 안전장치
평균은 안전하지만 극단 사용(켜놓고 잠듦, 봇)은 무한. 제안:
- 유료 플랜에 **남용 방지 상한**: 월 1,500분(하루 50분). 정상 사용자는 안 닿음. 닿으면 알림 1회.
- **세션 최대 길이** 2시간(자동 종료·저장).
- 사용자에게 잔량 표시 안 함(Free 제외).

$3.99/주 옵션. 전환율은 높으나 해지·환불 많고, 스토어가 주간 가격 표시 방식을 심사함. **넣는다면 정직하게 표시하고 연간을 기본 강조.** 안 넣어도 됨.

## 8. 결제 구조

### 스토어 결제 필수
디지털 구독은 Apple/Google 인앱 결제 의무(외부 결제 유도 시 리젝). 수수료 30%, **소규모 사업자 프로그램 신청 시 15%**(양쪽 다, 연매출 $100만 이하).

### RevenueCat 사용 제안
직접 구현 시: Apple/Google 영수증 검증 두 벌, 갱신/해지/환불/유예/재구독 웹훅 각각 처리, 구매 복원, 가족공유 — 수 주 작업 + 돈 관련 버그 위험.

RevenueCat이 대신하는 것:
- `react-native-purchases` SDK: 한 API로 두 스토어 결제, 페이월 UI 컴포넌트(서버에서 수정 가능)
- Entitlement: 앱은 `entitlements.active['plus']` 하나만 확인
- 웹훅 → Supabase Edge Function → `profiles.plan`, `plan_expires_at` 갱신 → 서버가 허용 여부 판단
- 대시보드: MRR, 해지율, 전환율, 가격 A/B 테스트
- 비용: MTR $2,500까지 무료, 이후 1%

### 구현 범위
1. 스토어 콘솔에 구독 상품 등록(계정 주인이 직접), RevenueCat 프로젝트 연결
2. 앱: SDK 초기화(Supabase user id를 RevenueCat app user id로), 페이월 화면, 구매/복원
3. DB: `profiles.plan`, `plan_expires_at`, `usage_minutes_month`, `usage_month`
4. Edge Function: RevenueCat 웹훅 수신(서명 검증) → plan 갱신
5. `process-session`/`converse`: 요청마다 plan + 사용량 확인, Free 한도/남용 상한 적용, 처리 후 분 수 가산
6. 앱: 한도 도달 시 안내 + 업그레이드 유도

**대안**: `expo-iap`/`react-native-iap`로 직접 구현 + 서버 검증. 수수료 1% 아끼지만 유지 부담 큼. **비추천.**

## 10. ChatGPT에 특히 묻고 싶은 것
